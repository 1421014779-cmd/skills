## I — 方法论骨架 (Interpretation)

应用记忆里的图像是流动的，不是一次画死就永远正确。第一次出图只要先有骨架；若提取时这张图把你带到了别的词上，说明「回忆导向」不准。

处理有两条路：
- **换图**：原来的物象本身就容易滑向别的目标，换一个更指向目标词的图像；
- **修饰**：不换底图，做二次加工，把容易滑走的点钉住。课堂例：本想记「准确」，却用了「靶子」，提取时可能浮出「目标」而不是「准确」；可在靶上加「红心中箭」一类细节，把导向拉回「准确」。

11/3 也提到「细节记不住可以修饰」，与本卡是同一条技术在后讲的用法。本卡负责：发现导向偏离 → 换图或二次加工，而不是把整组成编码推倒重来。

## A1 — 应用示例 (Application Example)

### 示例 1: 「靶子」滑向「目标」，用修饰拉回「准确」
- **类型与来源**: 原书例题 / 10/13
- **问题/输入**: 目标词是「准确」，图像用了靶子
- **方法论的使用**: 诊断为回忆导向不准；不换底图，二次加工（如红心中箭），让提取指向「准确」而不是「目标」。
- **结论**: 先识别滑向哪个近义词，再决定换图还是修饰。
- **结果**: 课堂用作操作示范；无延迟对照。

### 示例 2: 先骨架、后修饰细节（与 11/3 呼应）
- **类型与来源**: 原书原则 / 10/13，并与 11/3「细节记不住可以修饰」合并
- **问题/输入**: 第一稿图像只记住了大轮廓，细节提不出来
- **方法论的使用**: 允许先立骨架，再对记不住的细节做修饰，而不是要求第一稿就完美。
- **结论**: 图像是可迭代的。
- **结果**: 作为原则；11/3 侧是使用经验，不是新实验。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 编码时觉得图很清楚，一提取却说出了近义词或别的概念。
2. 细节总丢，但大图还在，不知道该重做还是局部加工。
3. 检查一组已有编码的「提取是否指向原词」。

### 语言信号

- 「回忆导向不准 / 看到图却想起别的词」
- 「要不要换图，还是修饰一下」
- 「细节记不住，怎么二次加工」
- 「靶子会不会记成目标」

### 与相邻能力的区分

- 与 `three-dimension-conversion` 的区别: 转化是首次出图；本卡是出图之后校准导向。
- 与 `loci-stability-audit` 的区别: 稳定四原则看位置本身站不站得住；本卡看「这张图指向的是不是目标词」。
- 与 `cued-recall-review` 的区别: 复习卡处理怎么提取；若提取稳定地导向错词，回到本卡改图。

## E — 可执行步骤 (Execution)

**必需输入**: 目标词/目标信息、现有图像、实际提取结果（提取出了什么）。若用户只说「记不住」而没有提取结果，先做一次有提示的提取，看导向偏到哪里。
**交付物与完成标准**: 保留、换图或修饰后的图像说明，并写明它应导向哪个词。完成标准：能指出原先滑向何处，以及改动如何把导向拉回目标词。

1. **做一次提取，记录滑向**  
   看图或想图，只写实际浮出的词，不要事后圆说成「其实是对的」。
2. **判断是换图还是修饰**  
   底图本身就强烈指向别的常用词（如靶子→目标）且不好救，倾向换图；底图大致正确、只是缺一个钉住目标的细节，做二次加工。
3. **只改导向相关的点**  
   修饰时加的细节必须服务于目标词，不要为好看堆无关装饰。
4. **再提取一次验收**  
   若仍滑向别处，再迭代；不要无限修饰同一张已经扭曲的图。
5. **判停**  
   问题其实是位置不稳或序列原则违规，转到对应卡。首次还没有图，转到三维转化。

## B — 边界 (Boundary)

- 「红心中箭」是课堂举例，不是唯一标准修饰。
- 不要把「图像是流动的」理解成可以随手改到失去与原文的对应。
- 本卡不处理「整组材料都还没有编码」的情况。

## 补充证据（10/19、10/20，增量合并）

10/19：「我们记所有东西就是，不是说一次记到位，就是先记骨架，然后的话慢慢的修饰」；编码回忆不流畅时，马上换掉或修改（动态体系）。

10/20 把图像的核心功能说死：「图像它的核心功能是要框定你的回忆导向。」并明确「逻辑做减法，图像做加法，这个是大错特错」。系统的出图验收见 `encoding-six-principles`；本卡仍负责已经偏了之后的换图或二次加工。
