# 第一性原理拆解

把一个问题拆到不能再拆的底层，抛开"大家都这么做"和现成方案，从基本事实重新推导路径。

## 何时用 / 何时不用

- **用**：方案兜圈子（修了几次没修到点上）、选型纠结、需求膨胀、调试陷入"打地鼠"
- **不用**：目标清晰、路径明确的执行任务——别为拆而拆

## 流程（严格两段式，顺序不可颠倒）

### 第一段：拆到底层（四分类，缺一不可）

1. **已确认、无法绕开的基本事实**——每条必须可核查，标注来源或验证方式
2. **习惯性接受、却没验证过的假设**——每条标注"如何证伪"。写不出假设 = 拆得不够狠，重来
3. **真正想实现的目标**——剥掉方案外壳后的用户意图（问：没有这个方案时，用户到底要什么？）
4. **现实中的资源与约束**——时间/钱/环境/合规的硬限制，不是想象中的限制

### 第二段：重新推导（四项输出，固定格式）

1. **原方案中只在修补表面的部分**——逐条点名，说明为什么它没触及根源
2. **从基本事实重新推导的新路径**
3. **这条路径成立的前提**——明确列出，让使用者知道什么情况下它会塌
4. **验证它的第一步**——必须 30 分钟内可执行，且验证成本显著低于原方案

## 质量红线（从真实踩坑中沉淀）

- **推断不得冒充事实**。案例：曾把"Nostr 国内不可用"（推断）当事实用于架构决策，而"境外 ≠ 不可达"刚被 pages.dev 实测推翻。推断必须标注"未验证"并给出验证方式
- **警惕验证层错配**。案例：dev 环境测试通过 ≠ 生产通过（满房拒绝在 dev 绿、生产坏）；mock 全绿 ≠ 浏览器能用（滚动容器 bug 只有真机暴露）。确认"你验证的东西"和"真实运行的东西"是同一个
- **修补表面的识别信号**：同一个区域反复出问题、补丁都有效但根源未动。案例：wrangler 本地冒烟反复卡死，各种修复都"有效"，根源是测试根本不该依赖重运行时——拆成纯逻辑层+薄胶水层后问题消失
- **区分"优化工程洁癖"与"满足用户需求"**。案例：用"对端回填"实现"离线留言"省掉了服务器状态，但回填的前提是"双方未来同时在线"——这与异步留言的真实场景可能根本不重合

## 实战锚点（e2ee-chat 项目，2026-09）

- wrangler 卡死 → 拆出"验证 15 行自有逻辑不该依赖 100MB 运行时"→ 纯逻辑/薄胶水分层
- 国内打不开 → 拆出"pages.dev 与 workers.dev 同公司不同命运"→ 实测后入口迁移
- 离线留言 → 拆出真正分歧是"用户使用模式"（同步约聊 vs 异步留言）→ 先问用户再写代码
- 房间密钥泄漏担忧 → 拆出"链接=钥匙"本质 → 钥匙拆两半（链接+口令）而非限制链接
